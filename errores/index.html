Errores web explicados

Qué significa cada error que puede tirar una web y qué revisar primero. Son los mismos fallos que Latido detecta y explica en sus avisos.

  • Error 500: el servidor falló al generar la página
    Qué significa el error 500 Internal Server Error, sus causas más habituales (plugins, .htaccess, PHP, base de datos) y qué revisar primero para recuperar la web.
  • Error 502 Bad Gateway: el intermediario recibió una respuesta inválida
    Qué significa el error 502 Bad Gateway, por qué aparece con Nginx, PHP-FPM o Cloudflare y qué revisar primero para que la web vuelva.
  • Error 503: la web no está disponible temporalmente
    Qué significa el error 503 Service Unavailable, sus causas (sobrecarga, mantenimiento, límites del hosting, protección anti-bots) y qué revisar primero.
  • Error 504 Gateway Timeout: el servidor tardó demasiado en responder
    Qué significa el error 504 Gateway Timeout, por qué el servidor de origen no responde a tiempo y qué revisar primero: consultas lentas, carga y tiempos de espera.
  • Error 403 Forbidden: el servidor se niega a mostrar la página
    Qué significa el error 403 Forbidden, cuándo es un bloqueo del firewall o de la protección anti-bots y no una caída, y qué revisar primero.
  • Certificado SSL caducado o no válido
    Por qué el navegador muestra «La conexión no es privada» (NET::ERR_CERT_DATE_INVALID), por qué falla la renovación automática del certificado SSL y qué revisar primero.
  • El dominio no resuelve: para internet, la web no existe
    Qué significa DNS_PROBE_FINISHED_NXDOMAIN o «el dominio no resuelve»: dominio caducado, DNS mal configurado o nameservers cambiados. Qué revisar primero.
  • Conexión rechazada: el servidor no acepta conexiones
    Qué significa ERR_CONNECTION_REFUSED o una conexión rechazada: el servidor web está parado, un firewall bloquea el puerto o el DNS apunta a un servidor antiguo.
  • La web no responde: se agotó el tiempo de espera
    Qué significa ERR_CONNECTION_TIMED_OUT o una web que no responde: servidor apagado, saturado o un firewall que descarta las conexiones. Qué revisar primero.
  • Demasiadas redirecciones: la web entra en un bucle
    Por qué aparece ERR_TOO_MANY_REDIRECTS: el SSL «Flexible» de Cloudflare, reglas de redirección que se contradicen o las URLs de WordPress. Qué revisar primero.
