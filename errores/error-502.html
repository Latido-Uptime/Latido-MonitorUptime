Errores web explicados

Error 502 Bad Gateway: el intermediario recibió una respuesta inválida

Entre el visitante y tu web suele haber un servidor intermedio: Nginx delante de PHP, un balanceador o una CDN como Cloudflare. El 502 significa que ese intermediario pidió la página al servidor de origen y recibió una respuesta inválida o ninguna.

Causas más habituales

  • El proceso que genera la página (PHP-FPM, Node, Apache) está caído, reiniciándose o bloqueado.
  • El servidor se quedó sin memoria y el sistema cerró ese proceso.
  • El intermediario apunta a una dirección o a un puerto que ya no corresponden al servidor.
  • Un firewall del servidor de origen bloquea al intermediario, por ejemplo a las IPs de Cloudflare.

Qué revisar primero

  1. Comprueba que el servicio de la aplicación (PHP-FPM, Node…) está en marcha y reinícialo.
  2. Lee el registro de errores del intermediario (por ejemplo, el error.log de Nginx): dice qué falló al contactar con el origen.
  3. Revisa el consumo de memoria y CPU del servidor.
  4. Si usas Cloudflare, confirma que el servidor de origen responde directamente y que su firewall permite las IPs de Cloudflare.

Cómo lo detecta Latido

Latido comprueba tu web cada pocos minutos. Si falla, repite la comprobación 5 segundos después y, si sigue fallando, te avisa por email con el motivo en español: «El servidor respondió 502». Cuando vuelve, te avisa otra vez con cuánto tiempo estuvo caída, y en tu panel queda la incidencia con un mensaje listo para reenviar a tu cliente.
