Errores web explicados

Error 403 Forbidden: el servidor se niega a mostrar la página

El servidor entendió la petición, pero no quiere servirla. Para un monitor de uptime hay un caso frecuente: la web funciona para tus visitantes y lo que hay es un firewall o una protección anti-bots que bloquea las comprobaciones automáticas.

Causas más habituales

  • Un firewall o una protección anti-bots (Cloudflare, Wordfence, ModSecurity, Imunify360) que bloquea robots o IPs de centros de datos.
  • Permisos de archivos o de carpetas incorrectos.
  • Una regla en .htaccess o en la configuración del servidor que deniega el acceso.
  • Restricciones por país o por IP.
  • Si el código es 401, la página pide usuario y contraseña; si es 429, el servidor está limitando las peticiones.

Qué revisar primero

  1. Abre la web desde tu navegador: si carga, revisa el firewall y permite las comprobaciones de Latido, que se identifican como LatidoMonitor.
  2. Revisa los permisos: lo habitual es 644 para archivos y 755 para carpetas.
  3. Busca reglas que denieguen el acceso o restricciones de IP en .htaccess y en la configuración del servidor.
  4. Si el 403 empezó al activar un plugin de seguridad, revisa su registro de bloqueos.

Cómo lo detecta Latido

Latido comprueba tu web cada pocos minutos. Si falla, repite la comprobación 5 segundos después y, si sigue fallando, te avisa por email con el motivo en español: «El servidor respondió 403». Cuando vuelve, te avisa otra vez con cuánto tiempo estuvo caída, y en tu panel queda la incidencia con un mensaje listo para reenviar a tu cliente.
